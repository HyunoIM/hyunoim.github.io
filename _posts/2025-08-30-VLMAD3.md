## VLM output

v4 프롬프트에서는 이상(NG)일 경우 defect_type을 함께 출력하도록 요구했고 실제로 모델은 다음과 같은 형태의 응답을 생성했다.

```json
{
  "verdict": "NG",
  "defect_type": "missing",
  "location": "top",
  "rationale": "The pill is missing a piece, making it incomplete and unusable."
}
```
또 다른 예시에서는 다음과 같이 출력되기도 했다.

```json
{
  "verdict": "NG",
  "defect_type": "crack",
  "location": "short",
  "rationale": "A crack is visible on the pill."
}
```

흥미로운 점은, 정상(OK) 이미지에 대해서도 NG + defect_type을 생성하는 경우가 빈번했다는 점이다.

```json
{
  "verdict": "NG",
  "defect_type": "crack",
  "location": "short",
  "rationale": "There is a crack in the pill."
}
```

위 예시는 실제로는 정상 capsule 이미지임에도 불구하고, LLaVA가 결함을 가정하고 그럴듯한 설명을 생성한 사례이다.

Vision-Language Model의 본질적인 특성이 드러난 결과로 볼 수 있을 것 같다.

VLM은 이상 여부를 판별하는 분류기라기보다는 이미지에 대해 가장 그럴듯한 설명을 생성하는 모델이다.

즉, 프롬프트에 결함 유형 후보를 제시하면 모델은 그 중 하나를 선택해야 하는 문제처럼 인식하고 실제로 확신이 없더라도 언어적으로 일관된 defect narrative를 만들어낸다.
이 현상은 일종의 hallucination 처럼 보인다.   

## v4 프롬프트의 특성

v4 프롬프트는 다음과 같은 특징을 가지는데,

- 카테고리별 defect type을 명시적으로 제공  
- NG일 경우 defect_type을 반드시 하나 선택하도록 요구  
- 출력 형식을 강하게 제한 (JSON)  

이로 인해 모델은  
“NG라고 판단되면, 반드시 의미 있는 결함 유형과 설명을 만들어야 한다.”  
라는 압박을 받는 것으로 보인다.

그 결과,

- Recall은 증가  
- False Positive도 함께 증가  
- 정상 이미지에서도 결함 서술을 생성하는 현상 발생  

---

## defect_type 정확도 (v4)

v4에서 defect_type accuracy를 별도로 측정한 결과는 다음과 같다.

- Exact match: 약 20~30%  
- Coarse match: 약 30~40%  

이는 모델이 결함의 존재 여부는 어느 정도 감지하지만 결함의 정확한 유형을 개념적으로 구분하지는 못한다는 것을 의미한다.

특히 capsule, zipper와 같은 미세 구조 기반 결함에서는 추론이 쉽게 과잉 해석으로 이어졌다.

## Observations

### 1. Prompt가 모델의 판정 성향을 결정한다

v0:

- Qwen2-VL → 모든 샘플을 NG  
- LLaVA → 모든 샘플을 OK  

즉, 명시적인 판정 구조가 없으면 모델의 prior에 따라 극단적 편향 발생한다.  
VLM은 anomaly detector가 아니라, 기본적으로 caption generator에 가깝다.

---

### 2. 구조화(JSON)는 Recall을 올리고, 설명은 Recall을 내렸다

v1:

- 판정만 요구 → recall 증가  

v2, v3:

- 설명을 요구할수록 NG 판단에 소극적  
- 정상 쪽으로 기울어짐  

설명 능력과 판정 능력은 동일하지 않다고 볼 수 있다.

---

### 3. v4: 카테고리 정보를 함께 주면 모델이 막연히 설명을 만들어내기보다, 실제 결함 유형을 기준으로 판단하는 경향을 보인다

v4에서는 defect type 정확도를 추가로 측정했다.   

<img src="{{ '/assets/images/vlm3/vlm34.png' | relative_url }}" alt="Image" width="400">   

완벽하진 않지만, 결함 후보를 언어적으로 제한하면 모델이 실제 defect 개념을 참조하기 시작한다.  
zero-shot 환경이라는 점을 고려하면 의미 있는 결과로 보인다.

## Discussion

VLM을 anomaly classifier로 바로 쓰기는 어려워 보인다.  
recall–precision trade-off가 심하고 defect classification 정확도 낮다.

하지만 설명 도구로는 충분히 가능성 있다.  
NG 후보를 필터링하고 결함 위치/유형에 대한 자연어 설명에 사용이 가능하다.

VLM은 Anomaly Detection 모델이 아니다. 하지만, Anomaly Detection에서 언어적인 인터페이스가 될 수는 있다.

주로 쓰이는 사전학습된 VLM을 가져와 프롬프트만으로 behavior가 바뀌는 모습  
이 자체로 흥미로운 실험이었다.
